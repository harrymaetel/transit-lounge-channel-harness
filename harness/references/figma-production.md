# Figma 제작 회귀 방지 · v0.3

이 규칙은 2026-10-31의 33장 제작에서 실제로 고친 결함에 적용한다. 사진·원고 선택과 장수는 콘텐츠에 따라 달라진다.

## 실행 환경과 원본 보호

1. 최신 프레임과 부모/자식 관계를 읽고 원본 ID, 복제본 ID, 헤더·콘텐츠·로고·슬롯 역할 ID를 기록한다.
2. 원격에서 Neulis Alt를 로드할 수 없으면 데스크톱으로 전환한다. 실제 loadFontAsync가 성공하기 전에 텍스트를 바꾸지 않는다. 폰트 파일을 배포하지 않는다.
3. 네이티브 플러그인은 `createFrame()` 후 layoutMode를 설정한다. MCP 확장인 createAutoLayout/query/screenshot을 네이티브 API에 그대로 쓰지 않는다. 네이티브 플러그인의 showUI/closePlugin은 원격 use_figma의 지원 여부와 다르다.
4. 로컬 개발 플러그인은 코드 저장 시 hot reload될 수 있다. 중복 생성 방지 ID/실행 영역을 확인하고, 쓰기 종료 후 창을 닫는다. 실행 오류 뒤에는 생성된 복제본부터 읽어 부분 실패를 복구한다.

## 텍스트와 컨테이너를 구분

- `resize(width, height)` → `textAutoResize='HEIGHT'` → 부모 Auto Layout 안에서 세로 `HUG` 순서로 설정하고 결과를 읽는다. characters/폰트/폭이 바뀌면 줄 수를 다시 측정한다.
- 원본의 648px 고정 텍스트 높이를 새 원고에 유지하지 않는다. 빈 줄로 레이아웃 여백을 만들지 않는다.
- Event 포스터 영역은 700×937 **FIXED**, 카드 루트는 1080×1350 고정. 본문 HUG 로직을 포스터/카드 루트에 적용하지 않는다.
- 사진 카드의 TEXT가 루트의 직접 자식일 수 있다. `text.parent`를 콘텐츠 프레임이라고 추정해 자식을 전부 제거하면 카드가 무너진다. 직접 TEXT는 해당 노드만 수정한다. 프레임 교체는 전용 콘텐츠 FRAME과 보호 노드가 겹치지 않을 때만 한다.
- 제목·본문·보조는 별도 TEXT. 추천 대상·프로그램·곡 순서는 독립 행/카드이며 프로그램 번호는 다음 페이지로 이어진다.

## 숨김·헤더·이미지

- 템플릿의 표지 보조문구가 visible=false일 수 있다. 새 원고에 포함한 슬롯은 조상 숨김·opacity·클리핑까지 확인한다. 사용하지 않는 예전 원고는 새 복제본에서 제거한다.
- `Transit`, 카테고리, 시리즈 제목의 역할 ID를 각각 관리한다. 글자가 같다는 이유로 모든 일치 노드를 지우지 않는다. 카테고리 기대값은 catalog.category_labels를 따른다.
- 프레임명/페이지 수/헤더/로고가 남았는지 검사한다. 사진과 설명이 맞아야 하며 기존 이미지 속 인용과 실명을 새 창작 문장의 출처로 사용하지 않는다.
- 사진 위 제목뿐 아니라 보조문구의 대비도 확인한다. 얼굴을 가리면 위치를 조정하고, 필요한 경우 기존 그라데이션을 보정한다. 자동 검사가 얼굴 가림·가독성·이미지 의미를 확인했다고 기록하지 않는다.

## 재사용 코드

`harness/scripts/figma_helpers.js`는 실제 실행 시에만 복사/로드하는 네이티브 함수 모음이다. setText는 최종 HEIGHT, replaceContent는 원본/루트/보호 노드 검사를 수행한다. captureFrame은 지정 역할 ID를 읽어 render 근거를 만들며 visual_review를 자동 통과시키지 않는다. 먼저 공식 Figma 스킬과 해당 환경의 API 지침을 로드한다. runs의 일회성 build/repair 코드와 실측 증거는 새 제작 스크립트나 승인값으로 재사용하지 않는다.
