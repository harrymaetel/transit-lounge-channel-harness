# Transit Calendar 제작 규칙

사용자 확정: 2026-11-06. [Figma 레퍼런스](https://www.figma.com/design/oloM9zVU0XkiwIYXcIT23R/Transit-Lounge?node-id=3049-77)를 기준으로 한다. 11월(S01), 12월(S02) 두 시안이며 가로가 한 세트다. 레퍼런스의 날짜·행사·사진은 확정된 신규 일정으로 재사용하지 않는다.

## 접수와 구성

`calendar` 선택 → 연도·월 → 일정 목록 → 소개할 행사 선택 → 필수 표지 이미지·선택 행사 이미지 → CTA 순서로 받는다. 실제 업로드는 첨부 가능한 채팅에서 요청한다. 표지가 없는 초안은 자료 요청 상태로 둔다. 텍스트 전용 표지나 임의 이미지로 대체하지 않는다.

완성본은 **표지 1장 + 월간 달력·목록 1장 이상 + 선택한 행사별 상세 1장씩 + 마지막 CTA 1장**이다. 레퍼런스 P03~P05는 세 가지 대안이지 필수로 모두 넣는 3장이 아니다. 소개 행사는 1~2개 또는 3개 이상 가능하다. 예: 행사 1개=4장, 2개=5장, 3개=7장(목록 2장). 목록은 모든 행사를 담고, 상세는 featured=true인 행사만 담는다.

| 역할 | S01 원본 | S02 원본 | 적용 |
|---|---|---|---|
| Cover-Image | 3090:1238 | 3064:2052 | 필수 표지 이미지 800×1071, 월 안내 |
| Month-Overview | 3049:126 | 3049:305 | 달력 + 일정 목록 |

원본명은 `TL/Calendar/S01/P01/Cover-Image` 형식이다. 신규 결과는 실제 순서대로 P01부터 번호를 다시 매긴다. 여러 행사에 같은 유형을 반복해도 된다. 헤더는 Transit / Calendar, 상세의 가운데 라벨은 `N월 행사 안내`로 갱신한다. 원본 CTA의 Event 라벨도 신규 복제본에서는 Calendar로 변경한다.

## 날짜와 행사명

- 연도는 생략해 추측하지 않는다. ISO 날짜를 기준으로 요일을 계산하며 `SUN MON TUE WED THU FRI SAT` 순서로 달력을 표시한다. 목록의 요일은 해당 날짜의 `MON`, `FRI` 등 세 글자 영문 대문자다.
- 텍스트 입력 예시: `11/13 FRI 19:30 – 22:00 : 북토크 워크숍`. 날짜와 요일이 다르면 확인을 요청한다. 잘못된 날짜·월 밖 행사·종료≤시작은 생성하지 않는다. 자정 넘김·다일 행사는 날짜별 일정으로 나눈 뒤 사용자의 확인을 받는다. 종일 행사는 all_day=true이며 ALL DAY로 표시한다.
- 일요일 시작의 실제 4~6주 달력을 만든다. 시작 전/종료 후 빈 칸을 남기고, 행사일의 selected=true 컴포넌트를 표시한다. 같은 날 행사가 여러 개면 날짜 표시는 한 번, 목록에는 전부 싣는다.
- 행사명 운영 상한은 공백 포함 NFC **20자·1줄**이다. 이는 원본의 실측 글자 수를 일반화한 보장값이 아니라 제작용 상한이다. 20자 이하라도 실제 폭을 넘으면 축약안을 제안한다. 원래 이름은 title, 축약안은 short_title에 보존하고 **사용자가 확인한 뒤에만** short_title_approved=true로 기록한다. 자동 말줄임·글씨 축소 금지.
- 레퍼런스의 목록은 **페이지당 2행**이다. 많으면 Month-Overview를 추가하고 목록을 2개씩 나눈다. 모든 달력에 월 전체 행사일을 표시하고 각 목록에는 해당 묶음을 한 번씩만 싣는다. 시간·행사명은 하나의 문단이 아니라 각 행의 별도 TEXT다.

## 이미지별 선택

이미지 없음 → Event-Text. 인물 또는 일반 사진 → Event-Photo 추천. 포스터 → Event-Poster 추천. 사진을 받았으면 Photo/Poster 중 하나를 사용하고, 사용자가 다른 방식을 고르면 detail_layout으로 명시한다. 인물 얼굴을 가리지 않고 보조문구 대비까지 확인한다. 포스터 안 날짜·행사명이 목록과 일치하는지 화면에서 읽어 확인한다.

## 글자·줄 수와 Neulis Alt

| 슬롯 | 최대 글자/줄 | 폰트 |
|---|---|---|
| 표지 월 안내 | 10 / 1 | Medium 40, 120% |
| 연도 / 영문 월 / 월 숫자 | 4 / 1 · 9 / 1 · 2 / 1 | Light Italic 56 · Bold 80 · Regular 164 |
| 목록 일정 / 행사명 | 25 / 1 · 20 / 1 | Regular 36, 150% |
| 상세 제목 / 본문 / 보조 | 28 / 2 · 60 / 2 · 50 / 2 | Bold 56 · Medium 48 · Medium 40, 150% |

상세의 전체 높이 예산은 512px, 블록 사이 40px다. CTA는 기존 cta 패턴 상한을 적용한다. 원고 글자 수와 최종 Figma 자동 줄바꿈은 별도로 검수한다. 달력용 **Light, Light Italic**을 추가로 실제 로드하고 나머지 페이지는 Regular/Medium/Bold를 유지한다. 누락 시 폰트 설치 동의를 받고 준비하며 대체 폰트나 임의 굵기로 바꾸지 않는다. 기본 설치 검사 3굵기 통과만으로 달력 폰트가 준비됐다고 판단하지 않는다.

## 제작·검수

1. calendar_content.py로 같은 행사 데이터에서 pages, grid, items, 카드 수를 생성한다. 초안 변경 후 재생성하면 QA·승인은 초기화한다.
2. 원본 복제 후 기존 날짜 셀·목록을 해당 월 데이터로 교체한다. 달력 날짜 영역 x=99.428부터 126.857 간격의 7열, y=275부터 행 간격 min(120,600/주수), 셀 폭120, 높이는 행 간격과 동일하다. 6주에는 100px 행을 쓴다. 날짜 TEXT는 셀 안에서 정렬하고 넘침을 확인한다. 목록은 y=955부터 62px 간격, 높이54인 독립 행이다.
3. 모든 텍스트는 최종 폭 설정 뒤 HEIGHT로 측정한다. 연도·월의 줄 상자 16px 겹침은 레퍼런스 예외지만 실제 글리프 겹침은 시각 검수에서 금지한다. 다른 겹침은 통과시키지 않는다.
4. captureFrame과 captureCalendarGrid로 실제 TEXT·요일·날짜·selected variant·셀 위치를 읽는다. render.calendar_grid에 측정 결과를 넣고, header.month_node_id와 이미지 roles.asset도 기록한다. 원고나 원하는 값을 측정값으로 복사하지 않는다.
5. 폰트, 표지, 날짜 누락/중복, 같은 날 복수 행사, 요일·행사일 강조, 목록-상세 일치, 장수·마지막 CTA, 포스터 비율·사진 대비를 검사한다. 사용자 검토용 화면을 만든 다음 승인받는다. 글자 한도 통과만으로 QA를 완료하지 않는다.

## 사용자 확정 카피 예외

사용자가 상세를 행사명·일정만으로 요청하면 events[].support를 빈 문자열로 기록해 보조 슬롯을 생략한다. 없는 가격·소개를 채워 넣지 않는다. 마지막 CTA는 calendar.cta_content의 title/body/support 중 필요한 슬롯으로 직접 지정할 수 있다. cta_text에는 사용자 확정 원문을 보존한다.
