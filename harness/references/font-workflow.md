# Neulis Alt 유지 워크플로

2026-10-30 사용자 확정: 기존과 신규 카드 모두 Neulis Alt를 유지한다. 이전 Pretendard 임시 치환은 복원 완료됐으며 앞으로 재발시키지 않는다.

## 새 컴퓨터에서 하네스를 설치할 때

1. 에이전트는 **Figma를 실행할 사용자 데스크톱**에서 저장소 루트의 `harness/scripts/setup_fonts.py --check`를 Python으로 실행한다. 종료 코드 0은 OS에서 세 굵기를 확인했다는 뜻이고, 1은 누락 또는 보류, 2는 확인 실패다. 원격·컨테이너의 결과로 사용자 PC의 설치 여부를 단정하지 않는다. Figma 데스크톱에서 세 굵기가 이미 로드되면 설치 단계를 마친다.
2. 빠진 굵기만 알려 주고 “라이선스가 있는 파일로 설치할까요, 제작사 다운로드 페이지를 열까요, 나중에 할까요?”라고 묻는다. 독립적인 개인 테스트일 때만 BeFonts 선택지를 안내한다. 기본값은 건너뛰기다. 보류하면 원고·구성 작업은 이어가고 필요한 디자인만 보류한다.
3. [BeFonts 배포본](https://befonts.com/neulis-font-family.html)은 개인용으로 표시돼 있다. 브랜드 SNS 제작에는 각 사용자가 권리를 가진 데스크톱 파일을 사용한다. [제작사](https://ladd-design.com/family/neulis/)는 Neulis Alt의 현재 제품명을 Neulis Neue라고 안내한다. 새 이름으로만 등록되는 제품의 경우 기존 Figma 문서 호환 여부를 구매 전에 확인한다. 폰트 파일을 공개 저장소에 넣거나 가족명을 고쳐 대체하지 않는다.
4. 동의 후 로컬 대화형 도구를 실행한다. 제작사 경로는 브라우저에서 본인의 라이선스로 파일을 내려받고, 개인용 경로는 BeFonts의 다운로드 버튼 주소를 브라우저로 연다. 파일이 ZIP이면 압축을 풀고 **정적 OTF/TTF가 직접 들어 있는 폴더**를 지정한다. 도구는 내부 영문 가족명·스타일로 설치 후보를 좁힌 후 파일 목록과 최종 확인을 표시한다.
5. macOS에서는 **서체 관리자**에서 현재 사용자 대상으로, Windows에서는 **글꼴 미리 보기**에서 설치한다. 설치 창이 열리지 않으면 [macOS 서체 관리자](https://support.apple.com/guide/font-book/fntbk1000/mac) 또는 Windows 설정의 **개인 설정 → 글꼴**을 사용한다. OS 설치 완료 후 Enter를 눌러 다시 검사한다. 마지막으로 Figma 데스크톱에서 세 굵기를 실제 로드한 뒤 제작한다.

## 제작 전

1. 수정 대상 텍스트의 fontName과 혼합 범위(fontName/fontSize/style)를 읽는다. 제목·본문·보조의 역할별 굵기는 design-system.md를 따른다.
2. 실제 실행 환경의 사용 가능한 폰트를 확인한다. Mac 설치와 원격 Figma 연결 도구의 폰트 목록은 서로 다를 수 있다.
3. Figma API에서는 현재 폰트와 사용할 Neulis Alt 굵기를 모두 await loadFontAsync로 로드한 후 텍스트를 수정한다. 설치 파일명과 family/style 식별자를 혼동하지 않는다.
4. 연결 도구에서 Neulis Alt를 로드할 수 없으면 먼저 데스크톱 앱에서 동일 파일·대상 레이어·설치 폰트 사용 가능 여부를 확인하고 데스크톱 UI로 편집한다. 이전 실제 작업에서 이 경로로 Regular/Medium 복원을 검증했다.
5. 둘 다 불가능하면 원본 서체를 보존한 채 원고·페이지 구조 작업을 진행하고 디자인을 font-blocked로 보고한다. Pretendard, Inter, 시스템 기본 서체 등으로 바꿔 완성 처리하지 않는다. 대체 서체는 사용자가 해당 작업에 명시적으로 지정한 경우에만 별도 예외로 다룬다.

## 제작 중

- 한글이라고 임의로 Pretendard로 치환하지 않는다. Figma 텍스트 속성의 Neulis Alt와 실제 한글 표시를 함께 확인한다. 글리프 지원 문제가 관찰되면 그 현상을 알리고 해결하며 승인된 한글 서체 조합을 지어내지 않는다.
- 제목 Bold, 본문 Medium, 브랜드 헤더 Regular를 유지한다. family만 바꿀 때도 섞여 있는 굵기를 한 가지로 평탄화하지 않는다.
- 로고는 원본 벡터다. 폰트 적용 대상에 포함하지 않는다.
- HTML·이미지 등 다른 산출물은 제공된 로컬 폰트의 사용 가능성과 사용 권한을 확인하고 실제 로딩 후 렌더한다. CSS family 문자열만 써 두고 브라우저 대체 폰트로 렌더한 결과는 통과하지 않는다. 폰트 파일을 자동 배포·업로드하지 않는다.

## 제작 후

수정 범위의 모든 텍스트 노드/혼합 범위를 다시 읽어 family=Neulis Alt와 역할별 style을 확인한다. 검사 결과에 대상 프레임, 슬롯별 텍스트 ID·실제 줄 수·overflow, font_runs, inspected_at, evidence를 기록한다. 폰트 변경 전후 줄바꿈·잘림·텍스트와 카드 경계·로고 간격을 실제 렌더로 확인한다. 자동 글자 수 검사는 이 검사를 대신하지 않는다.

데스크톱 일괄 선택이 필요하면 정확한 대상 ID/이름으로 범위를 제한한다. 임시 선택 표식을 쓰는 경우 원래 이름을 먼저 보관하고 완료 즉시 복원한다. 페이지 전체의 다른 Pretendard 작업까지 일괄 치환하지 않는다.


## 검증된 데스크톱 경로 · 2026-10-31

원격 연결의 목록에는 Neulis Alt가 없었지만 데스크톱 Plugin API는 Regular/Medium/Bold를 실제 로드했다. 원격 로드가 실패하면 서체를 치환하지 않고 데스크톱에서 로컬 스크립트를 실행할 수 있다. 실행 환경, 로드한 스타일, 확인 시점과 결과를 font_check로 남긴다. 폰트 파일을 업로드하거나 저장소에 넣지 않는다.

`fontName` 문자열만으로는 통과하지 않는다. 모든 텍스트의 혼합 범위와 missing font, 실제 렌더를 확인한다. 한글 글리프의 실제 표시도 확인하며, Figma가 내부적으로 선택한 글리프 대체까지 family 속성으로 증명했다고 쓰지 않는다. 로컬 플러그인과 원격 검사 도구의 환경을 혼동하지 않는다.

수정 이후 폰트를 새로 바꾸거나 대체해 검사를 맞추지 않는다. 새 텍스트를 복제할 때 현재 범위의 폰트를 먼저 로드하고, 사용할 스타일도 로드한 뒤 편집한다. 제작 범위의 전체 텍스트 수와 font_runs를 대조한다.
